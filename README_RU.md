# Связанные светом — v11 «Живое приключение»

Браузерный онлайн-платформер для двух игроков. Искра играет с компьютера, Эхо — с iPhone; роли назначаются по порядку входа. Основная кампания: 99 уровней в 11 мирах, 11 боссов, дополнительный секретный 100-й уровень, совместные головоломки, косметика, питомцы и домик.

## Запуск

- Node.js 20+.
- `npm start` — запуск HTTP/WebSocket сервера на `PORT` (по умолчанию 3000).
- `npm test` — все автоматические регрессионные тесты.
- На Render: Web Service из репозитория, команда `npm start`, проверка `/health`, ветка `main`.
- Оба игрока открывают один и тот же URL, ведущий создаёт комнату и отправляет код или ссылку. Гостю лучше открыть Safari и повернуть iPhone горизонтально.

## Нововведения версии v11

### Онлайн и отзывчивость

- Авторитетная серверная симуляция (60 шагов в секунду) и WebSocket-снимки 20 раз в секунду.
- Входные пакеты снабжены возрастающим номером `inputSeq`, сервер подтверждает обработанный номер в `ack`.
- Визуальное клиентское предсказание управляемого героя, плавная коррекция по состоянию сервера; интерполяция второго героя адаптируется к RTT и джиттеру.
- Индикатор диагностики: FPS, RTT, джиттер, буфер отображения. Высокий RTT по-прежнему влияет на время серверной активации объектов; предсказание не отменяет задержку сети.
- Переподключение в комнату после кратковременного обрыва сохранено. Опционально можно сохранять комнаты и токены на **постоянном серверном диске** через переменную `SAVE_DIR=/absolute/persistent/path`; это позволяет восстановить роли после перезапуска процесса. Без постоянного диска комнаты исчезают при рестарте Render.

### Управление и графика

- «⚙ Настройки»: автоматический/низкий/средний/высокий режим графики, размер кнопок 44–76 px, прозрачность, вертикальный отступ, расстояние от края, уменьшение анимаций, звук, диагностика соединения.
- Геймпад через стандартный Gamepad API: левый стик/крестовина — движение, A — прыжок, B — способность, X — связь, Y — эмоция.
- Исходные клавиши: Искра `A/D/W/F`, Эхо стрелки и `Enter`, `G` — связь, `T` — эмоция. Сенсорное управление работает на мобильных устройствах.
- Процедурные атмосферные звуки для 11 миров, звуки шагов/прыжков/способностей/боссов без сторонних аудиофайлов. Звук запускается после пользовательского нажатия с соблюдением ограничений Safari.

### Приключение

- Боссы имеют 3 фазы, меняют атаку и скорость атак на низком здоровье.
- В испытаниях с парусом Искра управляет курсом, Эхо заряжает парус импульсом.
- Активная световая связь может спасти упавшего героя, если второй находится рядом и стоит на земле.
- После этапа сервер присваивает 1–3 звезды с учётом времени, падений и использования способностей; лучший результат хранится в браузере и отображается на карте. Есть короткие вступления для каждого из 11 миров и реплики, которые можно выбрать и отправить второму игроку.
- Вкладка «Сейвы» позволяет скачать и импортировать JSON-файл прогресса (открытые уровни, звёзды, косметику, секреты, питомцев, обстановку домика). Это ручная резервная копия, **не автоматическая облачная синхронизация**.

## Состояние хранения на бесплатном Render

Бесплатные экземпляры Render могут засыпать и перезапускаться. Их локальная файловая система непостоянна, поэтому `SAVE_DIR` помогает только при использовании подключённого постоянного диска; на бесплатном тарифе нельзя гарантировать сохранность серверных комнат. Прогресс в браузере сохраняется в localStorage, но при очистке данных браузера он теряется. Экспорт JSON рекомендуется для резервной копии. Полноценная облачная синхронизация между устройствами потребует базы данных, аутентификации и защищённых резервных копий — пока она не реализована.

## Проверка

- `npm test` включает тесты 99 миров, сетевой синхронизации, боссов, мини-игр, выхода на 100-й уровень, спасения световой связью, оценок и подтверждений ввода, восстановления комнаты с диска, адаптивного буфера.
- UI проверен в Chromium в моделируемом окружении на размерах ПК и iPhone. Публичный Render и реальный мобильный Safari после этой версии нужно проверить дополнительно.

## Технические принципы

Механики и физика рассчитываются только сервером. Локальное предсказание влияет только на визуальную позицию собственного персонажа. Костюмы/дом/реплики синхронизируются в рамках комнаты. Все новые настройки сохраняются на текущем устройстве.

## Обновление v12 — коррекция движения, облачная синхронизация и регрессионные проверки

### Сеть: сервер остаётся авторитетным

- Клиент ведёт ограниченную очередь входных команд с `inputSeq`; сервер подтверждает команду **после** физического шага, а не при приёме пакета.
- `public/reconciliation.js` восстанавливает предполагаемое положение по последнему серверному снимку, проигрывает ещё не подтверждённые команды на фиксированном шаге 1/60 секунды, применяет базовые столкновения, а между снимками реагирует на местное управление без ожидания RTT.
- Результат мягко корректируется по серверу и ограничивается максимально допустимым расхождением. Взаимодействия с воротами, мостами, кристаллами, боссами и секретами по-прежнему принадлежат серверу.
- При смене уровня номера команд сохраняются, чтобы старые нажатия не повторялись как новые.
- Сложные силы отдельных биомов и взаимодействия второго героя всё ещё могут вызвать видимую коррекцию при плохой сети. **Это не бит-в-бит детерминированная клиентская симуляция всего игрового мира и не гарантия отсутствия рассинхрона при 500 мс.**

### Облако (дополнительная настройка владельца игры)

По умолчанию игра продолжает работать без базы данных. Чтобы включить постоянные сохранения между ПК и iPhone и восстановление комнат после перезапуска бесплатного Render, **создайте отдельный проект Supabase для игры** (не используйте чужие или несвязанные проекты).

1. Откройте SQL Editor нового проекта и примените `database/supabase.sql`. Обе таблицы имеют включённый RLS и закрытый доступ для `anon` и `authenticated`. Доступ есть только у серверного секретного ключа.
2. В Render → сервис игры → Environment задайте `SUPABASE_URL=https://<project-ref>.supabase.co` и `SUPABASE_SECRET_KEY=sb_secret_...` (если проект работает на старом ключе, можно использовать `SUPABASE_SERVICE_ROLE_KEY`). **Не вводите ключи в GitHub, в HTML, в публичный чат или в клиентский код.** После изменения переменных перезапустите сервис.
3. На игровой странице откройте «☁ Облако», создайте длинный случайный ключ восстановления, отдельно сохраните его и нажмите «Синхронизировать». На втором устройстве введите **тот же** ключ и синхронизируйте профиль. Ключ не заменяет шестизначный код комнаты и даёт полный доступ к сохранению — храните его как пароль.
4. При настроенном облаке профиль шифруется AES-256-GCM на сервере с ключом, производным от случайного ключа восстановления; в таблице хранятся только SHA-256 отпечаток ключа, ревизия и шифротекст. Обновления используют проверку ревизий, а секреты/награды и лучшие результаты объединяются, не заменяя более высокий прогресс меньшим. Общий домик и костюмы разрешают изменения по отметке последнего редактирования.
5. Сервер каждые 12 секунд пишет локальное состояние, а в облаке сохраняет зашифрованные комнаты (понадобятся ключи и SQL выше). После перезапуска сервер восстанавливает коды и токены комнат; оба игрока должны переподключиться. Если облако недоступно, сайт продолжает работать, но восстановление после полного перезапуска Render не гарантируется.

Важное ограничение: обычный импорт/экспорт JSON остаётся резервным способом. Код для облака готов, но до настройки **отдельного Supabase проекта** на Render сервер вернёт `enabled:false`, и в интерфейсе будет явно указано, что облако не подключено.

### Проверка

- `npm test`: регрессионные проверки игровой логики, сотни игровых шагов на каждом из **100 уровней**, генерации снимков, сетевой синхронизации двух клиентов, возвращения комнаты после перезапуска, корректного ACK, ограниченной коррекции, шифрования и конкурентных записей в имитацию хранилища.
- Chromium: локальная проверка рендеринга UI (ПК и горизонтальный формат iPhone) с имитацией соединения; ошибки JS отсутствуют. Это **не** замена реальному Safari.
- Автоматизированный бот с фиксированным алгоритмом прыгнул через часть уровней, но не прошёл все 99: такой тест сам по себе не доказывает непроходимость остальных. Полное прохождение всех 100 уровней вдвоём на реальных устройствах **не подтверждено**.

### Сетевые параметры

Все параметры остаются доступными в «⚙ Настройки»: графика, размер кнопок, FPS, RTT, jitter, звук и геймпад. Для тестирования задержки сравните показания RTT на обоих устройствах и проверьте плавность прыжков, стен, навыков и взаимодействия при длительных 300–500 мс.
## Google Login v13

Кнопка **G Войти** позволяет войти через Google на ПК и iPhone. Авторизация проходит через Supabase Auth с PKCE и зашифрованной HttpOnly-сессией на сервере Render. Гостевая кооперативная игра по коду комнаты сохраняется без обязательной регистрации. Google-аккаунт автоматически синхронизирует прогресс, домик, питомцев и костюмы через существующую таблицу зашифрованных сохранений.

Полная настройка, ограничения и проверка: [docs/GOOGLE_AUTH_RU.md](docs/GOOGLE_AUTH_RU.md). **Google Client Secret и SUPABASE_SECRET_KEY никогда не указывайте в GitHub или в браузерном JavaScript.**

## Установка игры как приложения (PWA v14)

**iPhone:** Safari → Поделиться → На экран Домой → «Открыть как веб-приложение» → Добавить.

**Windows:** Chrome / Microsoft Edge → «⬇ Приложение» или пункт «Установить» в меню браузера.

Приложение имеет собственный значок и запускается в отдельном окне. Для онлайн-кооператива нужен интернет, офлайн показывается экран переподключения. Google OAuth в iOS standalone может требовать Safari.

[Подробная инструкция](docs/PWA_RU.md).
