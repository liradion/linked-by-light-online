# Связанные светом v15.1 — уменьшение задержки кооператива

## Фактически изменено

| Параметр | До | После |
|---|---:|---:|
| Частота игровой физики (авторитетный сервер) | 60 Гц | 60 Гц (без изменения физики) |
| Снимки игрового мира при двух подключённых игроках | 20 Гц (каждые ~50 мс) | 30 Гц (каждые ~33 мс) |
| Отправка нажатых клавиш, пока идёт игра | 25 Гц (каждые ~40 мс) | 40 Гц (каждые ~25 мс) |
| Определение WebSocket RTT | Каждые 3 с | Каждую секунду |
| Клиентский буфер для удалённого игрока | 85–235 мс | Адаптивный, 48–165 мс (при устойчивых 30 Гц обычно ~48 мс) |
| Снимки неактивной комнаты | 20 Гц | 2 Гц; участники получают события подключения немедленно |

Кроме того:
- Активные действия (прыжок, способность, связь, эмоция) вызывают внеочередной снимок на ближайшем физическом такте.
- Авторитетное состояние сериализуется один раз и рассылается обоим игрокам.
- При переполнении очереди сокета на 24 КБ устаревший *снимок* пропускается вместо накопления задержки. Сообщения о комнатах и смене состояния не пропускаются этим правилом.
- Частота входящих сообщений по-прежнему ограничивается защитным лимитом сервера.
- Изменения не касаются сохранений Supabase, Google OAuth, мира v15 или конфигурации комнат.

Это уменьшает **задержку отображения и реакции управления**; нельзя обещать снижение сетевого RTT: он определяется маршрутом и расстоянием до дата-центра.

## Где проверить измерения

В меню игры: **⚙ Настройки → FPS и диагностика соединения**. На экране появятся:
- FPS — скорость отрисовки
- RTT — фактическое время до сервера и обратно, измеренное WebSocket-сообщением
- Джиттер — колебание сетевой задержки
- Буфер — дополнительное сглаживание движения второго игрока
- Снимки — фактически получаемая частота серверных обновлений

Сравнивать нужно в активной комнате, когда **оба игрока подключены и уровень запущен**. Сделайте 3–5 замеров по 30–60 секунд с ПК и iPhone. Не сравнивайте первые секунды холодного старта Render.

## Главный способ действительно снизить ping (RTT)

Render предоставляет регионы **Oregon, Ohio, Virginia, Frankfurt, Singapore**. Текущий регион нужно посмотреть в панели конкретного сервиса Render (в Settings/сводке сервиса), а не определять по домену.
Для игроков из Казахстана стоит отдельно сравнить Frankfurt и Singapore на обоих устройствах; географически близкий регион не всегда даёт лучший сетевой маршрут.

**Render не позволяет изменить регион существующего сервиса.** Нужно создать новый web service в выбранном регионе и скопировать:
- GitHub репозиторий `liradion/linked-by-light-online`, ветку `main`
- сборку `npm install --omit=dev`, запуск `npm start`, путь проверки `/health`
- существующую Environment Group Supabase (URL и секрет остаются только в Render)
- опционально `GAME_ORIGIN` для нового домена

Перенос может изменить веб-адрес. Тогда важно обновить Supabase Auth → **URL Configuration → Redirect URLs** для нового HTTPS-адреса игры. Site URL может оставаться старым до безопасного переключения, так как сервер явно задаёт `redirect_to`.

Оба сервиса можно временно держать отдельно для сравнения RTT. **Одна игровая комната не может растягиваться между двумя независимыми Render-сервисами**; оба игрока должны подключаться к одному и тому же URL.

Перенос текущих активных комнат между серверами не выполняется автоматически: перед окончательным переключением сохраните прогресс через Google. Старый сервис удаляйте только после проверки входа и сохранений на новом.

### Ограничения тарифа Free

Free-сервис засыпает после 15 минут без HTTP/WebSocket-трафика. После простоя может потребоваться холодный запуск; это проблема времени входа, а не пинга во время активной игры. Платный тариф устраняет холодный старт, но **сам по себе не гарантирует меньший RTT**.

Документация: https://render.com/docs/regions и https://render.com/docs/free
