# Linked by Light v22 — Public Beta: релизный регламент

**Статус:** кандидат в публичную бету. PR предназначен для review и автоматических проверок. Не равнозначен развёртыванию на Render и не заменяет ручное тестирование Windows / iPhone.

## 1. Что реализовано

- Онбординг из пяти шагов с объяснением комнаты, приглашения, совместного старта, управления и риска потери временных сохранений.
- Панель «Как играть» и форма отзывов «Отзыв» с явным согласием. Данные: тип, текст (10–800 символов), общая категория платформы, номер уровня, необязательная оценка. Не собираются имя, email, room token, ключ восстановления или точный IP в отчёте.
- Публичный `GET /api/beta/status` возвращает только агрегированную вместимость, активность комнат и признак **конфигурации** хранилища.
- Закрытый `GET /api/admin/v22/overview` предоставляет счётчики подключений, созданных комнат, восстановлений, завершённых уровней, p95 тика и задержки event loop, RSS, сохранённые отзывы и очередь карт.
- `POST /api/admin/v22/gallery` подтверждает / отклоняет карту. Новые авторские уровни имеют статус **pending** и скрыты, пока модератор их не одобрит.
- `v21Report` скрывает утверждённую карту после трёх жалоб и переводит её в состояние **flagged** до проверки.
- Отзывы, очередь карт и прогресс комнат включены в существующий серверный checkpoint. По умолчанию используется тот же формат данных `version:11` и те же таблицы Supabase.
- Усилены ограничения частоты создания комнат и входов с одного сетевого адреса. Для больших аудиторий за общим прокси нужна проверка справедливости ограничений.
- Время выключения сервера предусматривает попытку сохранить состояние до закрытия процесса. Нулевых потерь при аварии или отключении питания это не гарантирует.
- Проверка всех 122 уровней: инициализация, игровой тик, сериализация и перезапуск; отдельные интеграционные тесты для обратной связи, безопасности и восстановления данных.
- Добавлены информационные документы `/privacy.html` и `/terms.html`. Это **черновики**, а не юридически готовая документация коммерческого сервиса.

## 2. Конфигурация

| Переменная | Что делает | Требование |
|---|---|---|
| `PORT` | HTTP/WebSocket порт | Для Render задаётся автоматически |
| `BETA_MAX_ROOMS` | Ограничивает число комнат до 1–200 | На Render Free рекомендуется начать с `10` комнат, но это эксплуатационный ориентир, не гарантия нагрузки |
| `LL_ADMIN_TOKEN` | Разрешает закрытую операционную панель и ручную модерацию | Случайный секрет не короче 32 символов; **не** хранить в Git или frontend |
| `SUPABASE_URL` | Включает серверную базу при наличии ключа | Только отдельный проект Supabase игры |
| `SUPABASE_SECRET_KEY` или `SUPABASE_SERVICE_ROLE_KEY` | Доступ сервера к базе | Только секретное окружение Render |
| `SAVE_DIR` | Дополнительное сохранение в локальном каталоге | Только при **постоянном** подключённом диске, не при временной файловой системе Render Free |

Перед реальным публичным запуском настройте Supabase по `database/supabase.sql` с таблицами `linked_light_cloud_saves` и `linked_light_room_state`. Политики безопасности RLS не должны разрешать прямое чтение из браузера. На старте сделайте резервную копию отдельно от текущего checkpoint.

Если Supabase и постоянный диск не настроены, **данные комнат, галереи и отзывов временные**. Endpoint `/api/beta/status` показывает конфигурацию, но сам по себе не проверяет успешную запись в Supabase.

## 3. Управление модерацией

Новые уровни, созданные в редакторе, остаются в очереди до ручного решения. Без `LL_ADMIN_TOKEN` отправка авторских карт выключена; публичная игра и встроенные уровни продолжают работать.

Пример чтения очереди (замените адрес на собственный):

```bash
curl -H "Authorization: Bearer $LL_ADMIN_TOKEN" "https://linked-by-light-eu.onrender.com/api/admin/v22/overview"
```

Принять карту после проверки (вместо `ID` использовать 12-значный id из очереди):

```bash
curl -X POST "https://linked-by-light-eu.onrender.com/api/admin/v22/gallery" \
  -H "Authorization: Bearer $LL_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"id":"ID","decision":"approve"}'
```

Чтобы отклонить карту: `decision: "reject"`. Чтобы скрыть уже опубликованную: `decision: "hide"`. Команды допустимы только с действующим секретом. **Не публикуйте секрет в чате, записи экрана или сетевых логах.**

Ограничения текущей беты: нет полноценной панели модератора, расследования жалоб, механизма апелляций, распределённого rate limiting и антифрода на уровне аккаунтов. Галерею рекомендуется открывать для малой закрытой группы до внедрения этих механизмов.

## 4. Приём обратной связи

`POST /api/beta/feedback` принимает JSON с `kind: bug | idea | experience`, `message` не короче 10 и не длиннее 800 символов, `consent: true`, `platform`, необязательными `rating` и `stage`. Ответ `202` означает принятие сервером, не гарантирует внешнего резервного копирования.

Лимит: пять сообщений за час с одного сетевого адреса. В backup хранится максимум 100 последних отзывов. Администратор читает их в `GET /api/admin/v22/overview`.

**Конфиденциальность:** необходимо указать действующего оператора игры, контакт для удаления данных, законное основание обработки и окончательные сроки хранения до реальной публичной регистрации пользователей.

## 5. Smoke: локально и после Render

```bash
npm test
npm run smoke:deploy -- --url=http://127.0.0.1:3000
```

Для локального smoke отдельно запустите `npm start` на том же порту. В CI процедура автоматизирована.

После того как PR будет принят и Render развернёт `main`, проверьте:

```bash
npm run smoke:deploy -- --url=https://linked-by-light-eu.onrender.com
```

Или вручную запустите в GitHub Actions `v22 deployment smoke (read-only)`.

Проверяется строгая версия `22.0.0`, протокол 3, `/health`, `/api/beta/status`, HTML, JS/CSS, страница правил и страница конфиденциальности. Эта проверка **не создаёт комнаты, не отправляет отзывы и не нагружает игровой сервер**.

## 6. Протокол закрытой беты 10–20 пар

Для каждой пары выполнить следующие действия на Windows и Safari iPhone, отдельно записать результат и номер обращения:

1. Первое посещение: обучение читаемо на обоих устройствах, кнопки доступны на вертикальном и горизонтальном экране.
2. Ведущий создаёт комнату v21 и копирует ссылку; второй игрок входит без ручного ввода кода.
3. Оба подключены, роли различаются правильно, уровень запускается с подтверждением ведущего.
4. Два игрока проходят первый совместный уровень с реальным управлением и проверяют отсутствие рассинхронизации.
5. Проверить минимум по одному уровню в каждой из трёх кампаний, а затем пройти каждую карту при отдельном полном QA.
6. На iPhone погасить экран/переключить приложение, вернуться: роль и комната должны восстановиться.
7. Проверить потерю Wi-Fi и переключение на мобильную сеть, затем восстановление подключения.
8. Проверить Export / Import профиля и, когда настроен Supabase, восстановление после перезапуска сервера.
9. Послания видны только игрокам; наблюдатель не получает чужие личные письма.
10. Опубликовать тестовую карту: до решения модератора она невидима; после одобрения доступна в галерее.
11. Отправить отзыв и убедиться, что он виден только администратору и не содержит лишних данных.
12. Измерить долю успешных приглашений, пиковый CCU, p95 интервала тиков и частоту WebSocket-разрывов.

**Минимальные критерии для решения о запуске:** ноль известных критических ошибок, не менее 99% успешных приглашений в реальной выборке, подтверждённое сохранение после перезапуска, отсутствие потери роли при сетевом сбое, завершённый ручной QA основных уровней и готовые юридические реквизиты.

## 7. Зафиксированные ограничения

- GitHub CI, локальные контейнеры и Playwright-less Node WebSocket tests не доказывают визуальную работоспособность в Safari iPhone.
- Реальная вместимость на Render Free не гарантируется результатами контейнерной эмуляции.
- Агрегированная серверная аналитика сбрасывается при перезапуске и не является долговременной BI-системой.
- Отсутствует сторонняя аналитика и отслеживание отдельных пользователей; для оценки retention потребуется отдельная privacy-safe метрика.
- Без дополнительных средств контроля и юридической проверки выпуск следует считать **закрытой публичной бетой**, не коммерческим general availability.

## 8. Статус релиза

PR подготовлен для review. При зелёных CI проверены код и тесты; реальная версия Render подтверждается только GET `/version` и read-only smoke **после** фактического развёртывания. Не объединяйте PR с `main` до согласования выпуска.
