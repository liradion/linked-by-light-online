# Linked by Light v20 — нагрузочное тестирование (15 ноября 2026)

## Область измерений

Тест проводился в изолированном GitHub Actions runner с Node.js v22.23.4, Intel Xeon 6973P-C и четырьмя доступными логическими CPU.
Это локальный loopback-тест реальных WebSocket-клиентов в отдельных комнатах с двумя участниками. Сервер и генератор нагрузки работали на одном CI runner.
Публичный Render Free, сеть Казахстан–Frankfurt, реальные Windows/iPhone и зрители не подвергались нагрузке.

Команды:

```bash
npm run bench:load -- --cases=50,100,200,400 --duration=8 --warmup=2 --input-hz=25
npm run bench:load -- --cases=400 --duration=30 --warmup=3 --input-hz=40 --out=artifacts/soak
```

Каждая комната одновременно запускает игровой серверный уровень 100 (первый эпизод v20).
Каждый клиент отправляет игровой ввод, периодические ping, принимает и разбирает серверные JSON-снимки.
Замер серверной длительности тика включает игровую симуляцию и формирование/отправку пакетов. CPU измеряется как доля **одного** ядра.

## Что означает результат

- На данном runner сервер не достиг вычислительного потолка при **400 одновременных активных игроках** и двух игроках в каждой комнате.
- Программное ограничение `MAX_ROOMS=200` блокирует создание дополнительных комнат; превышение 400 играющих в этом тесте не проверялось.
- CPU, память и loopback RTT в CI нельзя считать прогнозом для Render Free, где ресурсы и сетевые условия отличаются.
- RTT в 0,34–5 мс не отражает интернет-задержку из Казахстана или с мобильного оператора.
- Продолжительность 30 секунд недостаточна для проверки утечек памяти на многочасовом сеансе.
- Не проверены 800 дополнительных зрителей, долгие разрывы сети, сетевые потери пакетов, задержки мобильного браузера, нагрузка Supabase и возврат комнат после рестарта.

## Безопасность

`/ __bench` (без пробела: `/__bench`) доступен только при установленном 32-байтном случайном токене `LL_BENCH_TOKEN`, с loopback-адреса и с корректным заголовком `x-bench-token`.
В обычном продакшен-процессе метрики **отключены**, маршрут не выдаёт информацию и возвращает 404.
Бенчмарк не использует реальные аккаунты, приватные комнаты и производственное облако; нагрузка создаётся на дочернем локальном процессе Node.js.

## Рекомендация

Оставить текущий программный предел **200 комнат / 400 активных игроков** до отдельного измерения на staging-экземпляре с ресурсами, идентичными Render Free.
Для полной оценки требуется длительный тест 10–30 минут, включая 40 Гц игровой ввод, наблюдателей, ограничение доступной памяти, распределённый сетевой RTT и сценарии переподключения.
Изменять максимум комнат автоматически по нагрузке без отдельной проверки не следует.
